# 设计边界

ELCLC 是 `net10.0` 类库. 它不依赖 WPF, 当前公开 API 包括 Minecraft 版本查询/加载器版本查询与兼容判断/Wiki 文本查询/Java 运行时发现/通用 HTTP 下载队列/文件日志和通用 JSON 文件存储.

## Core 负责

- 接受调用方提供的 `HttpClient`/来源选择/取消令牌和文件路径.
- 解析上游数据, 返回明确的数据类型与错误.
- 管理调用方指定目录中的日志轮换, 以及指定 JSON 文件的读写.
- 根据调用方提供的文件地址、目标路径和下载参数执行排队、分段、来源回退、校验与取消.
- 对已经支持的加载器组合给出保守的兼容判断.
- 从通用环境线索和调用方提供的目录查找、执行验证 Java; 不保存调用方的列表顺序.

## 调用方负责

- 决定数据目录/首选来源/网络代理和 `HttpClient` 生命周期.
- 选择异常展示/重试与记录日志的方式.
- 定义配置类型/默认值和校验规则; 决定界面/主题/窗口和平台集成.
- 从 Windows 注册表等平台来源提供额外的 Java 安装目录, 并保存用户排序及排除项.
- 收集游戏安装所需的文件清单、选择官方或镜像地址的优先顺序, 并实现安装/账户登录及游戏启动流程.

Core 不读取 ELCL 的 `LauncherSettings`, 不引用 WPF 或 Windows 注册表, 也不写死某个用户目录或盘符. Java 发现根据运行平台选择 `java.exe` 或 `java`, 并使用系统给出的用户目录及安装位置; 调用方可补充目录. 现有 API 可以用于兼容 .NET 10 的其他客户端, 不同操作系统上的运行结果仍需由接入方验证.

项目按实际需求扩展, 避免在 Core 中加入只能由某个页面解释的状态. ELCL 的页面状态与配置字段记录在[启动器文档](../launcher/README.md), 不作为通用 Core API 合约.
