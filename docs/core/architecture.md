# ELCL Core 架构

## 当前策略

项目当前采用"先写前端, 按需实现 Core"的方式推进: 先确定用户操作和页面状态, 再为真实需求设计最小 Core API, 避免写难以使用的大型工具类.

## 边界

`ErhioLab.Craft.Launcher.Core` 是不依赖 WPF 的 `net10.0` 类库. 它负责 Minecraft 领域逻辑和通用日志文件管理; 启动器项目负责界面/窗口生命周期/数据目录选择和 Windows 集成.

Core 中禁止直接依赖:

- WPF 或其他 UI 框架.
- Windows 注册表/WMI/`cmd.exe` 等平台专用能力.
- 写死的 `java.exe`/盘符或用户目录.
- 只能由某个页面理解的展示状态.

必须使用平台能力时, 先在 Core 中定义接口, 再由启动器或独立的平台层实现.

## 预备模块

以下只是方向, 不在当前阶段提前实现:

- Minecraft 版本清单与本地版本发现;
- Java 运行时发现与校验;
- 游戏启动参数生成与进程管理;
- Microsoft/Xbox/Minecraft 账户认证;
- 文件下载/校验与并发调度;
- Mod/资源包与整合包管理;
- 启动器配置和实例配置.

每个模块应优先采用异步 API/取消令牌和可测试的接口, 并避免把网络请求/JSON 模型/缓存和 UI 状态堆入同一个类.
