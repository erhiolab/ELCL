# 代码与注释规范

## 格式

- 遵循仓库根目录的 `.editorconfig`. C# 使用 4 空格缩进/文件范围命名空间; XAML 和项目文件也使用 4 空格缩进.
- 新增文件保存为 UTF-8, 并保留文件末尾换行. 格式化只调整排版, 不顺带改变界面或业务行为.
- `using` 按系统命名空间/项目命名空间分组; 同类成员集中放置, 长参数和初始化表达式分行.
- XAML 中复杂控件的属性每行一个; 简单且清晰的元素允许保持单行.

## 文档注释

- 类型/公开成员/跨文件使用的内部类型使用中文 XML 文档注释. 说明职责/参数含义和返回值, 不重复成员名称.
- 简单的事件处理器/自动生成的 `InitializeComponent` 调用和显而易见的属性赋值不逐行注释.
- 对窗口消息/平台互操作/动画状态和不直观的约束, 在相应代码旁加简短中文注释, 重点解释原因.
- 注释必须与代码同步更新; 不确定的行为不要写成既定事实.
- 注释使用中文说明和半角标点, 不使用全角逗号/句号/分号/括号等符号.

## 结构

- `MainWindow` 只负责窗口外壳/一级导航和侧栏/主体容器; 页面的内容放在对应视图中.
- Core 不引用 WPF 或 Windows 专有 API; 需要平台能力时在边界处定义契约.
- 新功能按页面需求逐步增加, 不预先建空模块.
