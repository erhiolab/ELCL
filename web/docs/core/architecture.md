# 接入约定

核心处理 Minecraft 数据和可复用工具，应用处理用户选择和界面。这样可以把 ELCLC 用在控制台、桌面或其他 .NET 应用中。

## 各自负责什么

| 核心负责 | 调用方负责 |
| --- | --- |
| 取得版本信息、解析元数据和安装计划。 | 选择来源、缓存结果、显示列表。 |
| 查找 Java、探测版本与架构。 | 保存优先级、决定本次使用哪个运行时。 |
| 下载文件、报告字节进度。 | 组织安装任务、控制队列入口与失败后的清理。 |
| 执行登录协议、返回会话。 | 提供应用 ID、打开网页、安全保存与刷新令牌。 |
| 合并版本、解压本地库、生成启动信息。 | 检查登录、运行命令、创建进程、管理日志与窗口。 |
| 在指定路径写日志、JSON 和安装档案。 | 定义配置结构、确定路径和用户提示。 |

加载器安装已实现。安装器需要执行 Java 时，核心生成 `ProcessStartInfo`，再交给调用方提供的回调运行，核心不接管游戏或安装进程的生命周期。

## 路径

`gameDirectory` 通常指包含 `versions`、`libraries` 和 `assets` 的游戏根目录。`versionDirectory` 指某个版本目录，`workingDirectory` 则是游戏运行时保存存档和配置的目录。

这几个路径可以不同。是否版本隔离由你的应用决定；ELCL 桌面端的固定隔离策略不属于核心 API 的限制。

## HTTP 客户端

网络类使用调用方提供的 `HttpClient`，不替你释放。建议在应用中复用连接，并在适当时设置超时、代理和请求头。

官方与 BMCLAPI 回退只作用于各 API 明确支持的端点，不是任意 URL 的通用镜像。具体来源和超时见对应页面。

## 取消与异常

异步方法提供 `CancellationToken` 时，可以由界面或任务系统传入取消令牌。主动取消通常抛出 `OperationCanceledException`，应与失败分开显示。

核心不会弹窗。网络错误、JSON 错误和文件权限错误交给调用方处理；部分 API 用专用异常保留阶段或多个来源的原因。

不要在出错后直接清空账户或覆盖损坏的配置。保留原文件和异常信息，用户才有机会恢复数据。

## 文件操作与进程

解析下载计划通常不会下载文件，但加载器的 `PrepareAsync` 会调用下载回调并解出安装包内容，各方法会明确说明副作用。

不要让版本重命名、删除、安装和运行同时修改同一目录。核心的目录边界检查不能代替应用的任务互斥。

运行重定向输出的 Java 进程时，应同时读取 stdout 和 stderr；取消等待并不等于结束进程，执行回调需要处理进程树的终止。

## 敏感信息

访问令牌和刷新令牌由调用方保存。完整启动参数、模板展开结果或服务响应可能包含令牌，不应直接写入日志。

`SessionFileLogger` 只负责写入，不会自动替其他模块脱敏。
