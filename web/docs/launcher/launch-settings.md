# 启动设置

入口：**设置 → 启动**。这里的设置用于之后点击启动创建的游戏实例，不会修改已经运行的游戏。

## 进程优先级

| 选项 | 效果 |
| --- | --- |
| 高 | 使用 Windows 的“高于正常”，优先照顾游戏，可能影响其他程序响应。 |
| 中 | 正常优先级，默认选项。 |
| 低 | 使用“低于正常”，适合希望给其他程序让出 CPU 的场景。 |

优先级不保证提升帧率，选择适合当前使用情况的档位即可。

## 游戏窗口

| 模式 | 行为 |
| --- | --- |
| 全屏 | 传入全屏参数。 |
| 默认 | 保留游戏自身的默认尺寸。 |
| 与启动器尺寸一致 | 按点击启动时的窗口尺寸和 DPI 计算宽高。 |
| 自定义尺寸 | 使用下方输入的宽度与高度。 |
| 最大化 | 等游戏窗口出现后执行最大化。 |

游戏窗口标题可以留空，也可以使用 `{user} - Minecraft {version}` 一类模板。标题模板与启动器自身的标题栏设置是两回事，标记说明见[高级启动选项](advanced-options.md#替换标记)。

## 内存分配

**自动分配**根据当时可用物理内存分段估算，不会把全部剩余内存都交给游戏。**自定义**使用可用物理内存的 0～100％，不是机器总内存的百分比。

例如机器共有 32 GiB，启动时可用 12 GiB，选择 50％时，计算基数是 12 GiB。

色条展示系统已使用、游戏计划分配和剩余部分。它是随采样变化的预览，不会提前占用内存；真正启动时重新计算。32 位 Java 最多分配 1024 MiB，最终不足 128 MiB 时会停止并提示调整。

容量和速度的显示单位可在[个性化](settings.md#容量与速度单位)中选择。

## 内存优化

点击卡片右上角的 **内存优化**，立即整理一次 Windows 进程工作集。勾选 **启动游戏前进行内存优化**，则会在每次启动准备中先执行，默认关闭。

这会将部分暂时不用的物理内存页交还系统，不会结束程序或删除文件。无权访问的进程会跳过；ELCL、本次前台程序和正在跟踪的游戏也会跳过。

程序再次读取数据时，占用可能回升，并可能短暂卡顿。这个功能不等于 Java 垃圾回收，也不保证提高帧率。百宝箱中的按钮执行的是同一项操作。

## Java 列表

启动时，ELCL 按列表顺序选择第一个兼容当前版本、且实际可以执行的 Java。点击 **查找 Java** 可重新查找，也可以手动添加、上下排序、移除，或打开所在文件夹。

普通查找会检查环境变量、系统登记和常见安装位置，不会逐盘遍历。手动添加时应选择 Java 可执行文件。主动移除的路径会记录下来，普通刷新不会立即把它加回。

没有列表时，启动器会尝试发现 Java；重置启动设置后也会重新发现。列表过长时可以展开和收起。

核心还提供[暴力搜索 API](../core/java.md#javadiscovery-findexhaustiveasync)，它不用于普通自动刷新。

## 高级选项与重置

Java 下方的高级选项包括 JVM 参数、游戏参数、启动前命令、垃圾回收策略与兼容设置，详见[高级启动选项](advanced-options.md)。

重置启动设置会恢复窗口、优先级、内存和高级选项的默认值，重新获取 Java；不会删除游戏或账户。
