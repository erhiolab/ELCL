# 导入整合包

还没有整合包文件？可以先到[下载 → 整合包](mods.md#下载或安装整合包)搜索，选择只下载文件，或直接安装为独立版本。

ELCL 可以读取整合包清单，安装对应的 Minecraft 和加载器，再下载包内声明的文件、导入配置与附加文件。

需要分享自己的版本？打开[版本设置 → 导出](modpack-export.md)，可以按分类或具体文件生成整合包。

## 从按钮导入

1. 在启动页打开 **版本选择**，先在左侧选好游戏文件夹。
2. 点击 **导入整合包**，选择 `.zip` 或 `.mrpack` 文件。
3. 在 **输入版本名称** 弹窗中填写新版本名称。默认填入整合包名称；弹窗会显示包内的 Minecraft 版本，以及目标游戏文件夹在版本选择页中的名称（包括自定义名称）。
4. 点击 **确认**，到任务列表查看安装进度。

名称为空、包含路径符号、已有同名文件夹或同名安装任务时，确认按钮不可用。不会覆盖或合并已有版本；请换一个名称。

## 双击 MRPACK 文件

在 **设置 → 其他 → 文件关联** 中点击 **绑定 .mrpack**。设为默认打开方式后，双击 MRPACK 会打开 ELCL，并显示与按钮导入相同的 **输入版本名称** 弹窗。点击确认后才开始安装。

同一目录的 ELCL 已在当前 Windows 用户会话中运行时，双击文件会唤起已有窗口，多个文件依次确认；已有窗口使用管理员权限也可以接收。安装目标仍是 ELCL 当前选择的游戏文件夹；同名版本不会被覆盖。取消关联、Windows 默认应用选择及移动启动器后的处理，详见[文件关联](settings.md#文件关联)。

## 拖入整合包

打开 **启动页** 或 **版本选择页** 时，把文件拖到启动器窗口内即可，左侧栏和右侧内容区都能接收。一次接收一个 ZIP 或 MRPACK 文件，会打开同一个命名弹窗，不接受文件夹。目标仍是当前选择的游戏文件夹。

支持普通权限拖放，也复用 Windows 原生接收方式处理管理员窗口。其他页面不接收整合包；版本设置的 Mods 页面仍只接收 Mods 文件。如果拖放不可用，可以用按钮选择文件。

## 支持的格式

识别以包内的清单为准，不依赖 ZIP 的文件名。清单可以位于压缩包根目录，或单层包装文件夹中。

| 格式 | 识别文件 | 导入内容 |
| --- | --- | --- |
| Modrinth | `modrinth.index.json`，格式版本 1 | 按依赖安装游戏与加载器，下载清单文件，再应用 `overrides/` 和 `client-overrides/`。客户端覆盖文件优先；仅服务端使用的下载项会跳过。 |
| CurseForge | `manifest.json`，`minecraftModpack` 格式版本 1 | 根据项目 ID 和文件 ID 获取具体文件，安装游戏与加载器，再导入清单指定的覆盖目录。 |
| MultiMC／Prism 实例导出包 | `mmc-pack.json`，格式版本 1 | 读取 Minecraft 与常见加载器组件，导入 `.minecraft/` 或 `minecraft/` 内的游戏文件。不导入原启动器的实例配置。 |

其他启动器导出的包，只要使用以上标准格式，也可以导入。例如，含 `modrinth.index.json` 的 PCL 导出 ZIP 按 Modrinth 格式处理，不依赖 PCL 配置。

普通游戏文件夹备份、服务端启动包、自定义 MultiMC 组件和其他未列出的格式不能直接导入。不支持或无法唯一识别的包会显示错误，不猜测里面应该执行哪个安装程序。

## 下载与目录

整个导入过程只创建一个任务，使用现有的游戏安装流程和多线程下载器。游戏版本清单、游戏文件和社区资源分别遵循各自的下载源设置，连接数与速度上限沿用下载设置。

新版本位于当前游戏文件夹的 `versions/输入的版本名称/`。Mods、存档、配置和附加文件放在这个版本内；`libraries/` 与 `assets/` 在游戏根目录共享。清单中的文件名保持不变，不附加 Mods 中文名，以免破坏整合包引用。

需要 Forge 或 NeoForge 安装处理器时，会使用 Java 列表中合适的运行环境；缺少可用 Java 时，任务会保留错误原因。导入完成后，在版本选择中选择新版本再启动。

CurseForge 文件遵守作者的第三方下载许可。文件不可获取时，任务会显示具体项目与文件标识，不猜测 CDN 地址绕过限制。导入只获取清单列出的文件，不自动另加前置 Mods；可选下载项也按清单导入，明确仅服务端使用的 Modrinth 文件除外。

## 取消或失败

任务可以取消；失败和取消的任务会留在任务列表中。点击 **移除** 时，清理这次新建的版本目录、安装工作文件和对应安装档案。已存在的其他版本及共享支持库、资源不会因此删除。源整合包也会保留。

失败任务可能已安装部分文件，不要把未完成的版本当成可用整合包。移除任务后可以重新导入。

导入会拒绝路径越界、符号链接、Windows 不安全文件名及重复归档路径，并检查文件大小与提供的校验值。清单最大 8 MiB，归档最多 100000 项，单个文件最大 8 GiB，声明的解压总量与下载总量分别最多 64 GiB。不会导入原启动器的账户、全局配置，也不会自动执行包内脚本。整合包本身仍应来自你信任的作者。

开始、完成和失败会写入 `ELCL/logs/`，接收拖放的记录位于 `DragDrop` 与 `Modpacks` 分类，下载和安装阶段沿用任务日志。
