# 文件与故障排查

文中相对路径以 ELCL 可执行文件所在目录为起点。游戏文件则位于版本选择中添加的各个游戏根目录。

## ELCL 的数据

| 路径 | 内容 |
| --- | --- |
| `ELCL/config.json` | 全局设置、Java 顺序、游戏文件夹与当前选择。 |
| `ELCL/accounts.json` | 账户列表与受保护的 Microsoft 令牌。 |
| `ELCL/cache/` | 版本信息、安装和运行等缓存。 |
| `ELCL/cache/skins/` | 皮肤、头像与披风图片缓存。 |
| `ELCL/cache/game-logs/` | 查看压缩日志时解压的临时文件，关闭查看页后删除。 |
| `ELCL/logs/Log1.txt` | 本次启动器日志。旧会话按编号后移。 |
| `ELCL/logs/game/` | 每次游戏进程的独立输出日志。 |
| `ELCL/installation-id` | 匿名统计使用的随机安装 ID。 |

服务的公开配置随程序内置，不需要自己创建 `services.json`。账户文件不参与普通配置导出。

## 游戏目录中的文件

| 路径 | 内容 |
| --- | --- |
| `versions/<名称>/<名称>.json`、同名 `.jar` | 已安装版本的启动元数据与客户端。 |
| `versions/<名称>/ELCL/settings.json` | 版本描述及独立启动设置，未覆盖的项目跟随全局。 |
| `versions/<名称>/ELCL/export-runtime/` | 导出脚本使用的本地库和补丁。 |
| `versions/<名称>/saves`、`mods`、`config` 等 | 隔离后的游戏数据。 |
| `libraries/`、`assets/` | 各版本共享的支持库与游戏资源。 |
| `launcher_profiles.json` | 与官方启动器兼容的安装档案。 |

不要把修改 ELCL 描述的需求写进 Minecraft 版本 JSON；这两类文件用途不同。

## 其他启动器的游戏文件夹

可以直接在版本选择中添加已有游戏文件夹。ELCL 会扫描其中的版本，安装档案同步不影响版本列表的使用。

部分启动器的 `launcher_profiles.json` 使用 GBK 等编码。ELCL 遇到非 UTF-8 或内容损坏的档案时，会保留原文件，在日志中记录同步失败，并继续显示扫描到的版本。无需为了使用这些版本而删除原档案。

## 找不到 Java

到 **设置 → 启动 → Java** 手动刷新，或添加一个已安装的 Java。运行时主版本必须与游戏兼容，单纯把最新 Java 排第一并不能保证所有旧版都能使用。

## 登录网页成功，ELCL 仍然失败

网页成功后还有 Xbox、Minecraft 令牌交换、授权和玩家档案验证。查看日志中失败的阶段；网络、账户限制和应用服务许可都可能影响后续请求。

不要把账户文件、访问令牌或完整启动命令发到公开 Issue。

## 安装或补全失败

在任务列表查看具体文件、来源或处理器步骤。403 通常是服务拒绝请求，404 可能是地址失效。共享文件存在不代表完整，补全会检查可用的大小和 SHA-1。

安装器生成的文件缺失且没有直链时，需要重新安装加载器，不能只反复补全原版资源。

## 游戏立即退出

先读任务提供的游戏日志路径，再看启动器的 `Log1.txt`。游戏日志包含进程输出；启动器日志记录检查、下载、参数准备和退出码，不能只看其中一份。

游戏窗口出现后，也可以点击运行任务旁的 **日志**，实时查看这个进程的输出。已经打开的日志页在进程退出后会保留，完整文件仍在 `ELCL/logs/game/`，详见[任务管理](tasks.md#查看实时-minecraft-日志)。

查找游戏自己保存的历史日志时，打开 **版本设置 → 日志**。这里读取当前版本的 `logs/`，支持直接查看 `.log`、`.txt`、GZip 与 ZIP 中的日志，详见[版本日志](version-settings.md#查看版本日志)。

如果要提交问题，请说明游戏版本、加载器、Java、复现步骤和失败阶段，并附上相关日志。清理垃圾会删除日志，排查前不要先清理。
