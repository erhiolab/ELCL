# 启动游戏

在账户管理中选好账户，再选择一个已经安装的游戏版本，点击启动页左侧的版本按钮即可启动。准备过程会出现在任务列表里，可以查看正在处理哪一步，也可以取消。

## 启动前会检查什么

1. **账户和授权**：离线账户使用本地玩家信息；Microsoft 账户会检查访问令牌、Minecraft Java 版授权和档案，必要时刷新登录。验证失败会停止启动并弹出提示，不会悄悄改成离线账户。
2. **版本信息**：读取所选版本的 JSON，合并它继承的父版本。缺失的官方父版本 JSON 会尝试获取；无法取得的自定义父版本需要先安装。
3. **内存优化、Java 和分配**：如果勾选了启动前内存优化，先整理 Windows 工作集，再按当时可用物理内存计算分配量。按设置中的 Java 顺序选择第一个兼容且能执行的运行时；没有兼容 Java 时会提示去设置中添加。
4. **文件完整性**：校验游戏 JAR、支持库、资源索引、日志配置和资源文件，缺失或损坏的可下载文件会自动补全。使用设置中的文件下载源、并发连接数和限速。
5. **准备进程**：解压本地库、生成参数、执行启动前命令，然后创建 Java 进程并等待游戏窗口出现。

所选版本文件夹或 JSON 已不存在时，会提示重新选择或下载安装。加载器安装过程中生成的文件若没有下载地址，ELCL 会提示重新安装，不会用原版文件去覆盖它。

## 启动设置如何应用

| 设置 | 行为 |
| --- | --- |
| 进程优先级 | 高对应 Windows 的“高于正常”，中为“正常”，低为“低于正常”。 |
| 全屏 | 向游戏传入全屏参数。 |
| 默认窗口大小 | 保留游戏自己的默认尺寸，不附加自定义宽高。 |
| 与启动器尺寸一致 | 按启动器当时的尺寸与 DPI 换算游戏宽高。 |
| 自定义尺寸 | 使用填写的宽度和高度。 |
| 最大化 | 游戏窗口出现后执行最大化。 |
| 游戏窗口标题 | 窗口出现后应用标题模板；包含时间标记的标题会持续更新。留空保留原来的游戏标题。 |
| 自动内存分配 | 按当前可用内存估算，沿用设置页的分段算法。 |
| 自定义内存分配 | 使用当前可用物理内存的指定百分比；32 位 Java 最多分配 1024 MiB，不足 128 MiB 时停止并提示调整。 |
| 启动游戏前进行内存优化 | 默认关闭。开启后在启动准备任务中整理一次 Windows 工作集，再计算游戏内存；优化失败会提示并继续启动，取消任务则停止准备。 |

参数、GC、启动前命令及兼容补丁的说明见 [高级启动选项](advanced-options.md)。设置在点击启动时固定下来，准备过程中修改设置会用于下一次启动。

ELCL **固定使用版本隔离**，没有额外的隔离开关。游戏工作目录和 `--gameDir` 使用所选版本文件夹，例如 `.minecraft/versions/1.21.1/`。游戏的 `mods`、`config`、`saves`、`resourcepacks`、`screenshots`、日志及 `options.txt` 因此各自保存在版本目录中；启动前命令的相对路径也以这个目录为准。

`libraries` 和 `assets` 仍在 `.minecraft/` 下共享，不会复制进各个版本。旧版资源索引要求的 `resources/` 映射会放进当前版本目录；`assets/virtual/` 映射仍位于共享资源目录。本地库会解压到每次启动独立的缓存目录，退出后再清理。ELCL 不读取其他启动器的隔离开关，也不会把 Prism 实例转换为标准版本目录。

## 与官方启动器共用安装档案

ELCL 启动时会在启动器旁的 `.minecraft/` 中创建 `launcher_profiles.json`，并在后台登记这里已经安装的版本。打开版本选择页、切换或刷新游戏文件夹时，也会将扫描到的版本登记到**该游戏文件夹内**的档案文件中。手动添加的文件夹同样适用；已有文件和其他启动器的条目会保留。

安装原版完成或成功启动已有版本后，ELCL 会登记该版本的名称、版本 ID 和隔离目录。官方启动器读取这份文件时可以看到对应的安装配置。重复安装或启动同一目录会更新同一条档案，启动成功后更新最后使用时间。

扫描已有版本不代表启动游戏，不会刷新最后使用时间；没有变化时也不会重写文件。文件夹里没有可识别的版本时，`profiles` 为空是正常的。档案按游戏文件夹分别保存，例如启动 `E:/Minecraft/PCL2/.minecraft/` 中的版本，记录就写入那里的文件，而不是启动器旁的 `.minecraft/`。

如果游戏文件夹中已经有 Microsoft Store 版使用的 `launcher_profiles_microsoft_store.json`，ELCL 也会同步自己的条目。删除版本时只清理 ELCL 登记的档案，其他启动器创建的条目会保留；移除未完成安装的任务时也会清理本次新建版本的档案。

这个兼容文件不会替换 ELCL 自己的设置和账户文件，也不会导入官方启动器的账户、当前选择或 Java 参数。已有文件损坏、无法写入或检测到其他程序修改时，ELCL 会保留原文件并记录错误；同步失败不会阻止游戏安装和启动。

## 内存优化

在 **设置 → 启动 → 内存分配** 卡片右上角点击 **内存优化**，可以立即执行一次整理。下方的 **启动游戏前进行内存优化** 会将相同操作加入每次启动的准备任务，默认不勾选；重置启动设置后也会恢复为关闭。

ELCL 使用 Windows 的 [`K32EmptyWorkingSet`](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset) 整理同一 Windows 会话中允许访问的进程工作集，把部分物理内存页交还给系统。无需管理员权限；无权访问、受保护或已经退出的进程会跳过。本启动器、当前前台进程以及 ELCL 正在跟踪的游戏进程也会跳过。整理不会结束其他程序、删除文件或改变程序申请的虚拟内存大小。

这和高级选项中的 **垃圾回收策略** 不同，不会要求 Minecraft 执行 Java GC，也不能修复内存泄漏。程序再次使用相关数据时会重新载入，占用可能回升，并可能出现短暂卡顿。是否增加可用内存取决于当时的系统状态，不保证提高帧率；没有明显增长时，通知也会如实说明。

手动优化会用通知条报告开始与结果，日志记录优化前后的可用内存、成功和跳过的进程数量。优化在后台进行，按钮会临时禁用；启动前的优化以任务阶段显示。同一时刻的请求会等待同一次优化，不会重复扫描。

## 取消、失败和日志

游戏窗口出现后，准备任务会交接为以游戏名称显示的“正在运行”任务，列表中会显示对应的进程 ID 和 **终止** 按钮。关闭任务页不会关闭游戏；点击终止会立即结束这次启动的 Minecraft 进程及其子进程。每个任务绑定具体的进程实例，不会按 `java.exe` 进程名结束其他游戏或 Java 程序。

正常退出或主动终止后，运行任务会自动移除；没有其他任务时，任务管理页面会退出。运行任务没有下载进度，也不参与下载与安装任务的总进度计算；只有游戏运行时，左侧改为显示运行数量。终止失败时会显示错误并保留任务，可以再次尝试。

取消准备任务仍会取消下载、结束仍在等待的启动前命令和本次刚创建的游戏进程；已经下载好的共享支持库与资源会保留。

失败任务会留在列表中显示原因。窗口出现前进程就退出时，任务会报错并给出日志位置。窗口出现后的异常退出也会保留运行任务，并使用通知条提示退出码和日志位置。主动点击终止不会被当作崩溃提示。

- 启动器的检查、补全、命令开始与结束等操作写入 `ELCL/logs/Log1.txt`。
- 每次游戏进程的输出保存在 `ELCL/logs/game/` 中的独立文件，访问令牌和刷新令牌会脱敏。
- 自定义命令的原文和输出不写进日志，避免泄露用户自己填写的密钥；只记录开始、结束与退出码。

不等待完成的启动前命令会和后续启动同时运行，不能用来保证某个文件已经生成。需要游戏依赖它的结果时，请勾选等待选项。
