# 启动游戏

先在[账户管理](accounts.md)中选好账户，再在[版本选择](versions.md)中选择一个已安装版本，点击启动页的启动按钮。

准备过程会加入[任务管理](tasks.md)。如果尚未选择账户，或版本目录已经不存在，ELCL 会提示先处理，不会直接创建游戏进程。

## 启动前会做什么

| 阶段 | 检查内容 |
| --- | --- |
| 账户 | Microsoft 账户验证会话、Java 版授权和档案，必要时刷新；离线账户使用本地信息。 |
| 版本 | 读取 JSON，合并父版本信息；缺失的官方父版本会尝试获取。 |
| 内存与 Java | 按需优化内存，再计算分配量；使用版本指定的 Java，或自动选择列表中第一个兼容且能运行的 Java。 |
| 游戏文件 | 默认校验客户端 JAR、支持库、资源索引、日志配置和资源，下载缺少或损坏的文件。关闭文件校验后只补充缺失文件。 |
| 创建进程 | 解压本地库、生成参数、执行启动前命令、运行 Java，等待游戏窗口出现。 |

Microsoft 账户验证失败时会停止，不会自动切换为离线账户。安装器生成且没有下载地址的文件缺失时，需要重新安装对应加载器。

窗口、内存、Java 和优先级见[启动设置](launch-settings.md)；参数和命令见[高级启动选项](advanced-options.md)。[版本独立设置](version-settings.md#版本独立启动设置)优先于全局，未覆盖的项目跟随当前全局值。设置在点击启动时确定，之后的修改用于下一次启动。

## 同时启动多个游戏

启动准备期间可以再次点击启动。每次点击都会建立独立任务，可以启动不同版本，也可以多次启动同一版本。

各实例有独立的本地库缓存、日志和进程记录，终止一个不会结束其他实例。正在安装或修改版本文件时，需要等待相关任务完成。

同一版本的多个实例仍共用存档、模组、配置和 `options.txt`。ELCL 不复制这些内容；同一个世界是否允许同时打开，由 Minecraft 判断。每个实例单独计算内存，准备任务之间不会预留配额。

## 查看和结束游戏

窗口出现后，启动任务会变成以游戏名称显示的运行任务，包含进程 ID 和 **终止** 按钮。

关闭任务页面不会关闭游戏。点击终止会结束这个实例及其子进程；正常退出或主动终止后，任务会自动移除。

异常退出会保留错误任务并给出日志位置。游戏还没出现窗口就退出时，也会作为启动失败处理。

## 版本隔离

ELCL 的游戏工作目录和 `--gameDir` 都是当前版本目录，例如 `.minecraft/versions/我的版本/`，没有额外的隔离开关。

`libraries`、`assets` 仍共享。本地库按每次运行单独解压，结束后清理。旧版的 `resources` 映射放在版本目录，`assets/virtual` 映射留在共享资源目录。

## 与官方启动器共用档案

ELCL 会在各游戏文件夹的 `launcher_profiles.json` 中登记已安装版本，包括名称、版本 ID 和隔离目录；已有 Microsoft Store 档案文件时，也会同步 ELCL 自己的条目。

扫描只登记版本，不更新最后启动时间。成功启动后才标记使用时间。已有档案和未知字段会保留，损坏文件不会被自动重置；同步失败会记入日志，不阻止游戏启动。

这不导入官方启动器的账户或参数，也不替代 ELCL 的配置与账户文件。

## 启动失败后

先打开任务列表查看失败阶段。需要进一步排查时，查看 `ELCL/logs/Log1.txt` 和 `ELCL/logs/game/` 中本次游戏的日志。

常见处理方法见[文件与故障排查](files.md)。
