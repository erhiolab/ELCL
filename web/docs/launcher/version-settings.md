# 版本设置

在启动页点击“版本设置”，或在版本列表中点击某个版本右侧的齿轮，即可打开它的设置页。左侧目前提供“概览”。页面固定管理打开时的那个版本，不会因为启动页后来选择了别的版本而改变目标。

顶部显示“版本选择 - 游戏版本号”。概览中的信息行与版本列表使用同一个组件，显示图标、名称、说明和版本标签，不再单独显示路径或分隔线。这里不提供自定义图标。返回按钮会回到进入前的启动页或版本列表。

## 个性化

点击“修改版本名”，填写名称后确认。这个操作会修改实际版本目录、版本 JSON 的 `id`、同名 JSON 和 JAR 文件，并保留实际 Minecraft 版本信息。存档、模组和配置随目录一起移动，启动器的当前选择、文件夹记忆和安装档案也会更新。

同名目录或文件已存在时不会覆盖。版本仍有启动、运行、安装、补全或其他文件任务时，需要先结束任务；其他版本通过 `inheritsFrom` 或 `jar` 引用它时，也不能直接重命名或删除。重命名出错会尝试恢复原来的名称和元数据。

缺失或损坏 JSON 的目录仍能进入概览，打开目录、修改名称或删除。修改名称不会自动修好其中损坏的元数据。

“修改版本描述”可以填写最多 256 个字符的说明。设置后，版本列表和概览的第二行会显示“描述　类型标签　游戏版本标签　加载器标签”；例如“常用存档　正式版　1.21.1　NeoForge 21.1.265”。留空并保存会恢复原来的版本类型说明。错误版本仍会优先显示解析错误，避免描述盖住故障原因。

描述保存在这个版本目录内的 `ELCL/settings.json`，与 Minecraft 自己的版本 JSON、启动器全局配置分开。目前这个文件保存版本描述，后续可在同一处扩展独立设置；现有启动选项仍使用全局配置。移动或重命名版本目录会一起保留描述，重启启动器后也会重新读取。修改描述会保留文件中其他已有字段；文件无法读取时不会直接覆盖它。

## 快捷方式

可以打开版本目录，以及其中的存档、截图、光影、材质包和日志文件夹。支持模组的加载器版本，或已经存在 `mods` 的版本，还会显示 Mod 文件夹入口。子文件夹尚不存在时，会在这个版本目录中创建后打开；版本本身已经被移除时不会重新创建它。

这些入口遵循 ELCL 的版本隔离：例如存档位于 `versions/<版本名>/saves`，模组位于同级 `mods`。共享的 `libraries` 和 `assets` 不会移动到版本目录内。

## 补全文件

“补全文件”会创建一个可取消的任务，读取版本及继承链，检查客户端 JAR、支持库、资源索引、日志配置和游戏资源的大小及 SHA-1，下载缺少或损坏的文件。使用设置中的文件下载源、连接数和限速，不要求登录账户，也不会启动 Java 或游戏。

补全不会删除模组、配置或存档。加载器安装处理器生成、但没有可用下载地址的文件无法直接重新下载；遇到这种缺失，需要重新安装对应加载器。元数据本身无法读取时，也需要先重新安装。

## 导出启动脚本

选择保存位置后，ELCL 会选择 Java、校验游戏文件并生成一个 `.bat` 文件，不在导出位置生成附属文件夹。导出时不会执行启动前命令，也不会启动游戏。

导出不要求登录，也不验证或刷新 Microsoft 账户。已选择账户时仅使用本地保存的玩家名称和 UUID；没有账户时使用默认的离线玩家 `Player`。访问令牌使用离线占位值，不会把账户中的访问令牌或刷新令牌写入脚本；它不提供正版在线会话。

启动数据和执行代码都在 `.bat` 内，执行时使用 Windows 自带的 PowerShell，避免批处理命令长度与特殊字符的限制。本地库和兼容补丁准备到版本目录内的 `ELCL/export-runtime/`。脚本仍依赖这些文件、当前 Java 和游戏目录的绝对路径，不是可分发的整合包；移动或重命名版本、移动 Java 后请重新导出。

执行脚本时才会执行已配置的启动前命令，再运行游戏。内存、参数和窗口标题使用导出时生成的值；进程优先级和窗口最大化会在脚本启动游戏时应用。它不负责刷新登录、不运行 ELCL 的启动前内存优化，也不把游戏接入 ELCL 的任务列表。

完整启动命令和玩家参数不写入启动器日志。需要正版在线功能时，请通过启动器正常登录并启动游戏。

## 删除版本

删除前会要求确认，然后仅删除这个版本的目录及其内容，包括该版本内的存档、模组和截图。共享支持库、资源和其他版本会保留。删除后会清理启动器中的选择记忆与安装档案，版本列表也会刷新。请先备份需要保留的游戏数据。

重要操作会进入日志，后台任务的进度和错误在任务列表中显示；右下角任务按钮在版本设置中也可使用，返回任务页后会保留当前版本设置。
