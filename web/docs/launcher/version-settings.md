# 版本设置

在启动页点击 **版本设置**，或点击版本列表某一行右侧的齿轮。页面管理打开时选定的版本，返回后回到原来的启动页或版本列表。

概览顶部显示图标、名称、说明和版本标签，与版本列表使用相同布局。左侧依次提供 **概览**、**设置** 和 **日志**。

## 修改版本名称

在 **个性化** 卡片中点击 **修改版本名称**，输入名称并确认。

这会修改实际目录、同名 JSON 和 JAR、元数据的安装 ID，不只是改显示文字。存档、模组、配置和独立描述随目录保留，ELCL 的当前选择、文件夹记忆与安装档案也会同步。

已有同名目标不会覆盖。版本正在启动、运行、安装或补全时不能改名；被其他版本继承或引用客户端时也会阻止。

重命名失败会尝试恢复原名称和元数据。缺失或损坏 JSON 的目录也能改名，但不会因此变成可启动版本。

## 修改版本描述

在 **个性化** 中点击修改版本描述，最多填写 256 个字符。设置后，概览和版本列表第二行显示为：

```text
常用存档  [正式版] [1.21.1] [NeoForge 21.1.265]
```

留空并保存，会恢复默认版本类型说明。描述太长时省略显示；错误版本仍优先显示解析错误。

描述保存在版本目录的 `ELCL/settings.json`，不修改 Minecraft 的版本 JSON，也不写入全局配置。重新打开、移动或重命名版本后仍能读取；保存会保留其他扩展字段，损坏配置不会被直接覆盖。

同一文件也保存这个版本的独立启动设置，见下方说明。

## 版本独立启动设置

打开左侧 **设置**，可以单独调整当前版本的 Java、启动选项、内存分配和高级选项。布局与[全局启动设置](launch-settings.md)一致，修改后自动保存，已经运行的游戏不受影响。

页面直接显示当前生效的值：没有单独修改的项目使用全局设置，修改过的项目使用版本自己的值。不需要逐项选择是否跟随全局。

保存时只记录与当时全局设置不同的项目。改回全局值，这一项便会从版本配置中移除，以后继续随全局变化。例如，全局内存比例为 50％，把某个版本改成 70％只影响这个版本；再改回 50％，便恢复同步。

将鼠标移到左侧 **设置** 上，点击右侧的单箭头重置图标，可以一次清除当前版本的启动修改，保留描述，不改变全局设置和 Java 列表。

### 选择 Java

- **自动选择**：按照全局 Java 列表的顺序，选择第一个兼容且可执行的 Java。
- **使用指定的 Java**：展开 Java 选择器，从列表中选择。旁边的刷新按钮使用普通 Java 查找更新列表；也可以先在全局启动设置中手动添加。

指定模式会强制使用所选 Java，即使它不符合版本的自动兼容性规则。请自行确认兼容性；路径失效或无法执行时会停止并提示重新选择，不会自动换用另一项。

### 启动选项与内存

进程优先级、窗口大小、内存分配和启动前内存优化的用法与全局启动设置一致。选择自定义窗口后可以填写宽高；自定义内存仍按当时可用物理内存的百分比计算。

游戏窗口标题同样支持[替换标记](advanced-options.md#替换标记)。清空标题后，当前版本使用游戏自己的标题；填写与全局相同的标题则恢复同步。

### 高级选项

JVM 参数、游戏参数和启动前命令可以直接编辑。清空表示不添加这项附加文本或不执行命令；只要与全局内容不同，就会保留为当前版本的设置。JVM 参数旁的重置按钮会恢复当前全局 JVM 参数，并移除这一项的独立值。

垃圾回收策略、等待命令、兼容补丁、显卡偏好和证书验证也可以分别覆盖，具体效果见[高级启动选项](advanced-options.md)。参数预览使用当前正在编辑的版本。

**关闭文件校验** 通常保持关闭。开启后，启动准备只检查文件是否存在，不再检查已有文件的大小与 SHA-1；缺失文件仍会下载，新下载文件仍会校验。损坏的现有文件可能导致启动失败，可回到概览点击 **补全文件** 完整检查。版本 JSON 和资源索引仍必须能够正常读取。

独立设置随版本目录一起保留，重命名后也继续生效。文件无法读取时会保留原文件并阻止保存和启动，请先检查版本文件夹中的 `ELCL/settings.json`。

## 打开常用文件夹

可以快捷打开版本、存档、截图、光影、材质包和日志文件夹。带模组加载器或已有 `mods` 的版本，还会显示 模组文件夹入口。

子文件夹不存在时会创建；版本本身已经被移除时不会重建整个版本。所有入口都遵循版本隔离，打开的是当前版本内的数据。

## 查看版本日志

打开侧栏最下方的 **日志**，查看当前版本 `logs/` 文件夹中的 `.log`、`.txt`、GZip（`.gz`）和 ZIP 日志。列表按修改时间从新到旧排列，显示名称、时间和大小；文件夹不存在时显示空状态，不会创建空目录。

双击一项，或选中后点击 **打开日志**（也可以按 Enter）。ZIP 中有多份日志时，会分别列出包名和成员名，方便直接选择。点击 **刷新列表** 重新扫描，或点击 **打开文件夹** 到资源管理器中查看。

日志查看器与运行任务中的界面一致，支持换行、级别筛选、搜索、复制和原始文本。普通日志可以继续接收文件的新内容；压缩日志查看解压时的内容。大文件仍使用[日志查看器的显示限制](tasks.md#查看实时-minecraft-日志)，完整文件不会被截断。

压缩日志只解压选中的一份到 `ELCL/cache/game-logs/` 下的独立临时目录，单份解压后最多 512 MiB。返回日志列表、切换版本或页面、关闭版本设置或正常退出启动器时，会删除这次的临时文件，原日志与压缩包保留。强制结束启动器可能留下缓存，可以通过百宝箱清理。

损坏的压缩包也会出现在列表中，打开失败时通知原因并记录到启动器日志。这里只扫描当前版本日志目录的直接文件；ZIP 中的 `.log` 和 `.txt` 可以位于子目录。崩溃报告仍在版本的 `crash-reports/` 中。

## 补全文件

点击后创建任务，检查客户端、支持库、资源索引、日志配置和资源，按可用大小与 SHA-1 下载缺少或损坏的文件。

无需登录，不启动游戏，不删除存档或模组。来源、连接数和限速使用[下载设置](download.md)。

元数据无法读取，或加载器产物缺失又没有下载地址时，需要重新安装，补全不能代替安装处理器。

## 导出启动脚本

选择保存位置后，只生成一个 `.bat`，不在旁边创建附属文件夹。导出使用当前版本的独立设置和继承后的全局值，包括 Java 和文件校验选项；不会当场执行启动前命令或游戏。

不要求登录，也不刷新 Microsoft 账户会话。使用所选账户的本地玩家名与 UUID，没有账户时使用离线玩家 `Player`。脚本不会包含账户令牌，无法用于需要在线验证的服务器。

执行时使用 Windows PowerShell 读取 BAT 内嵌的启动数据，兼容长参数和特殊字符。本地库与补丁留在版本的 `ELCL/export-runtime/` 下。

脚本仍依赖当前 Java、游戏目录与运行文件的绝对路径，不是可分发整合包。移动 Java 或版本后应重新导出。

运行脚本时才执行已配置的启动前命令，然后启动游戏；应用导出时的内存、参数、窗口标题、优先级和最大化选项。不刷新登录、不执行 ELCL 的内存优化，也不接入 ELCL 的运行任务列表。

## 删除版本

删除前需要确认。确认后删除整个版本目录，包括其中的存档、模组、配置和截图；共享支持库、资源和其他版本保留。

有相关任务或被其他版本引用时不能删除。成功后清除当前选择和 ELCL 登记的安装档案，刷新列表。请先备份需要保留的数据。

## 查看操作结果

进度和错误在[任务列表](tasks.md)中显示，重要操作写入日志。设置页面也可以打开任务列表，关闭任务页后回到版本设置。
